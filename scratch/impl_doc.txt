0. Reconciliation Summary
This document supersedes the earlier proposal-based preparation document. It is written directly against the project's current README.md, so every requirement, story, and schema entry below is tagged as either Implemented (present in the code/endpoints) or Planned (mentioned in the README's Future Enhancements or Core Features text but not yet backed by a module, endpoint, or table).
Area
Original Proposal
Current Implementation

Resume Rewriting
Grounded, evidence-based rewrite suggestions

Match Scoring
Keyword + semantic similarity, weighting unspecified
Weighting is now explicit: 40% keyword, 60% semantic
Auto-Apply
Per-listing opt-in via Playwright automation
Described as a Core Feature but has no endpoint, no automation dependency, and no log table
External Jobs
Aggregated, deduplicated, ranked into the feed
Aggregation is designed but results are not persisted — no ExternalJobs table
Gap Report
Separate, structured entity linked to a match score
Flattened into a JSON column on MatchScores

4. Database Schema (as implemented)
This reflects the schema exactly as documented in the README: five tables, no separate profile tables, and the gap report stored inline as JSON rather than as its own entity.

Fig 1. Entity-Relationship Diagram of the current implementation, with a callout for entities implied elsewhere in the README but absent from the schema.
4.1 Table Reference
Table
Key Columns
Notes
Users
id, email, hashed_password, full_name, role, created_at
role ∈ {seeker, employer}; no separate profile table
Resumes
id, user_id (FK), file_path, parsed_data (JSON), text_content
parsed_data comes from pattern matching, not an LLM
JobPostings
id, employer_id (FK), title, description, requirements (JSON), location
on-platform postings only
MatchScores
id, resume_id (FK), job_posting_id (FK), overall_score, keyword_match, semantic_match, gap_report (JSON)
single table serves both matching directions
Applications
id, applicant_id (FK), job_posting_id (FK), resume_id (FK), match_score
match_score appears duplicated from MatchScores rather than referenced by FK
